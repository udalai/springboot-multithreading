How to Verify It Works

• Check the console logs: When you hit /usersByMultiThread, you should now see log lines printing thread name: userThread-1, userThread-2, and userThread-3

• Keep corePoolSize(2) if testing queuing: If you intentionally want to watch 2 threads process 3 tasks (where one thread handles two tasks back-to-back), leave corePoolSize and maxPoolSize at 2.

============

From the caller's perspective (whether a browser, Postman, React/Angular frontend, or RestTemplate/WebClient), nothing changes at all—it receives a standard HTTP 200 OK response containing a single flat JSON array ([ {...}, {...} ]) of all combined User objects.

How Spring Handles the Response Under the Hood

• Unwraps the CompletableFuture automatically: Spring MVC sees that the controller returns CompletableFuture<ResponseEntity<List<User>>> and suspends the HTTP response without tying up a Tomcat worker thread.
• Sends standard JSON once complete: As soon as CompletableFuture.allOf(...) finishes and .thenApply(...) returns ResponseEntity.ok(combined), Spring serializes the List<User> into JSON via Jackson and sends it to the client.
• What the HTTP response looks like:json
[
  {
    "id": 1,
    "name": "Alice",
    "email": "alice@example.com"
  },
  {
    "id": 2,
    "name": "Bob",
    "email": "bob@example.com"
  }
  // ... followed by the items from users2 and users3
]
Use code with caution.

How Different Callers Consume It

• Browser or Postman: Simply send a GET request to http://localhost:8080/usersDataByMultiThread. The client waits until all three background threads finish and renders the combined JSON array just like any normal synchronous endpoint.
• JavaScript (fetch / React / Angular): Consume it with standard await response.json()—no special async stream handling is required on the frontend.javascript
const response = await fetch("http://localhost:8080/usersDataByMultiThread");
if (response.ok) {
    const users = await response.json(); // Standard JavaScript array of User objects
    console.log(`Loaded ${users.length} users`);
}
Use code with caution.
• Spring WebClient or RestClient: Call .bodyToMono(new ParameterizedTypeReference<List<User>>() {}) or .body(...) as you would for any regular List<User> endpoint.

One Small Detail to Keep in Mind

• Error response body: In your .exceptionally(...) block, ResponseEntity.internalServerError().build() returns an HTTP 500 status with an empty body, so any frontend caller should check if (!response.ok) before calling response.json() to avoid a JSON parse error on failures.
